## 重构 web 部分：配置化云端同步 + 访问码 + 转换器

基于探索结果：`web/index.html`（约 1150 行，纯静态转换器，含搜狗/百度/微软二进制等格式解析、表格编辑、多格式导出）、`web/xiaohe-setup.html`（配置指南页）。当前无任何配置加载与云端同步逻辑。仓库已有 `.env`（S3 配置）和 Python 上传脚本，但无 GitHub 同步。

按推荐默认方案实施（fetch `web/.env`、访问码加密凭证、配置默认源+可切换、保留全部现有功能、默认搜狗格式）。

### 1. 新增配置文件

- **`web/.env.example`**（提交到仓库）— env 格式，键包括：
  - 访问码：`ACCESS_CODE_HASH`（访问码的 SHA-256 十六进制值，用于页面解锁比对）
  - 同步目标：`SYNC_TARGETS=s3,github`（逗号分隔，页面按此显示可选目标，可单选/多选）；`DEFAULT_SOURCE=s3`（点击"加载"时默认源，页面可下拉切换）
  - S3：`S3_ENDPOINT_URL`、`S3_REGION`、`S3_BUCKET`、`S3_PATH`、`S3_FILENAME`、`S3_PUBLIC_URL`（公开读的下载基础 URL）、`S3_ACCESS_KEY_ID` / `S3_SECRET_ACCESS_KEY`（**用访问码 AES-GCM 加密后的密文**，格式 `enc:v1:<salt_b64>:<iv_b64>:<data_b64>`）
  - GitHub：`GITHUB_REPO`、`GITHUB_BRANCH`、`GITHUB_PATH`、`GITHUB_FILENAME`、`GITHUB_TOKEN`（同样加密存储）
- **`web/.env`** — 本地实际配置（模板复制后填写），`.gitignore` 中确保被忽略（已有 `.env` 规则，验证是否覆盖子目录；如被忽略则 example 通过 `!web/.env.example` 例外放行）。

### 2. 改造 `web/index.html`（保留全部现有转换/编辑功能）

- **访问码解锁门**：页面打开后显示全屏解锁遮罩，输入访问码 → Web Crypto SHA-256 与 `ACCESS_CODE_HASH` 比对 → 通过后用访问码派生密钥（PBKDF2）AES-GCM 解密 S3/GitHub 凭证（仅存内存/sessionStorage，不写入 localStorage）。未解锁时页面主体不可用。获取不到 `.env`（本地打开、CORS 等）时降级：提示错误，仅保留本地导入/导出功能。
- **云端短语卡片**（置于导入区上方，作为新的导入来源）：
  - "加载短语"按钮：点击后才从配置源拉取短语文件（S3 公开 URL 直接 GET；不可公开读则用签名 GET）。源可下拉切换（S3 / GitHub，默认 `DEFAULT_SOURCE`）。
  - 拉取到的内容走现有解析管线（默认按**搜狗格式**解析，保留自动格式检测），进入现有表格编辑。
- **上传替换（更改）**：编辑完成后点击"上传替换"：
  - 目标按 `SYNC_TARGETS` 显示为复选框，可只选一个或多个，同时上传。
  - 导出内容默认搜狗格式（导出格式选择器默认 `sg`，仍可选其他格式）。
  - **S3**：在页面内实现 AWS SigV4 签名（基于 `crypto.subtle`，约百行 JS，不引入 SDK）发起 PUT；状态区提示需要给 bucket 配置 CORS 允许 PUT（附示例 CORS 配置）。
  - **GitHub**：GitHub Contents API（`PUT /repos/{repo}/contents/{path}`），先 GET 现有文件 sha 再替换提交，commit message 自动带时间戳；页面显示提交结果链接。
- **配置生成器**：页脚入口（或 `?gen=1`）打开弹窗：输入访问码与明文凭证 → 输出加密后的 `.env` 内容供复制粘贴，方便生成配置文件，无需额外脚本。
- **页脚"配置命令与下载"卡片**：把现在藏在文件头注释里的内容做成可见的可复制区块——小鹤双拼 `reg add` 命令、PowerShell 下载 `ChsPinyinEUDPv1.lex` 命令、手心/搜狗短语在线下载地址、GitHub release EXE 下载链接、以及指向 `xiaohe-setup.html` 的完整配置指南链接。
- 清理现有误加的 `xiaohe-setup.html` 链接（header/footer 中的多余 `<a>`），统一到新页脚区。
